# 회원가입 및 이메일 인증 흐름

작성 기준: 2026-06-18

## 목표 흐름

```text
POST /api/v1/auth/signup
-> PendingRegistration 생성 또는 갱신
-> 인증번호 발송
-> User 미생성

POST /api/v1/auth/verify-email
-> PendingRegistration row lock
-> 인증번호 검증
-> transaction.atomic()
-> User 생성
-> is_verified=True
-> PendingRegistration 사용 완료
-> 로그인 가능
```

## Signup

1. Public API라 Authorization header가 없어도 동작한다.
2. 이미 인증된 `accounts_user.email`이면 `EMAIL_ALREADY_REGISTERED`로 차단한다.
3. 기존 미인증 User는 legacy 호환 재발송 경로를 사용한다. 자동 삭제나 Pending 자동 변환은 하지 않는다.
4. 새 가입은 `PendingRegistration`에 저장한다.
5. 비밀번호는 평문을 저장하지 않고 Django password hash만 저장한다.
6. 필수 이용약관과 개인정보 동의가 false면 signup을 차단한다.
7. SMTP 실패 시 인증번호 hash를 무효화하고 User는 생성하지 않는다.

## Verify

1. `email`, `code`를 body로 받는다.
2. Pending row를 `select_for_update()`로 잠근다.
3. 이미 사용된 Pending이면 `REGISTRATION_ALREADY_VERIFIED`를 반환한다.
4. 만료, 잘못된 코드, 최대 시도 초과는 User 생성 없이 종료한다.
5. 성공 시 transaction 안에서 `User`를 1건 생성하고 `is_verified=True`로 저장한다.
6. Pending은 `is_used=True`, `verified_at` 기록으로 재사용을 차단한다.
7. 같은 인증번호를 중복 제출해도 User 중복 생성은 발생하지 않는다.

## Resend

신규 회원가입은 `POST /api/v1/auth/verify-email/resend`를 사용한다. 재전송은 Pending 기준으로만 동작하며 User를 생성하지 않는다.

TTL과 제한값:

```text
인증번호 TTL: 600초
재전송 쿨다운: 60초
최대 시도 횟수: 5회
```

## Legacy 미인증 User 운영 점검

기존 미인증 User는 자동 변환하지 않는다. 운영자는 다음 읽기 전용 명령으로 현황을 확인한다.

```bash
python manage.py list_legacy_unverified_users --limit 100
```

원문 이메일 출력이 필요한 운영 점검은 승인 후 다음 옵션을 사용한다.

```bash
python manage.py list_legacy_unverified_users --show-email
```
