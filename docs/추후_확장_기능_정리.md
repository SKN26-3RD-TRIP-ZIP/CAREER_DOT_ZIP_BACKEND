# 추후 확장 기능 정리

> 현재 발표 범위에서는 보류하고, 추후 확장으로 정리한 항목입니다.
> 우선순위: 高(다음 스프린트) / 中(여건 시) / 低(장기).
> DB 변경이 필요한 항목은 "임의 변경 금지" 원칙에 따라 **제안 단계**로만 둡니다.

| 기능 | 현재 상태 | 보류 사유 | 추후 구현 방향 | 우선순위 |
|---|---|---|---|---|
| 1. 비밀번호 재설정 API/화면 | 백엔드 API 없음, FE는 "추후 제공" 문구만 | 토큰 저장/메일 흐름 + 보안 검토 필요 | `POST /auth/password-reset/request|confirm`(무상태 서명토큰 또는 토큰 테이블) + 재설정 화면 | 高 |
| 2. 회원 탈퇴 API/화면 | 백엔드 API 없음 | 데이터 삭제 범위/소프트삭제 정책 결정 필요 | hard-delete(`DELETE /auth/me`, 연관 파일 정리) 또는 soft-delete(`status=withdrawn`, **DB 변경**) + 확인 모달 | 高 |
| 3. 장기 미이용 계정 정지(dormant) | 미구현 | 상태값 확장 = **DB 변경**, 배치 필요 | `User.status`에 `dormant` 추가 + last_login 기준 배치/스케줄 | 中 |
| 4. refresh 토큰 만료 UX 완전 고도화 | 401→refresh→실패 시 로그인 이동 + 세션만료 안내(기본) | 토큰 블랙리스트/슬라이딩 세션 등 추가 설계 필요 | 만료 임박 알림, 자동 재발급 UX, 서버측 blacklist(`token_blacklist` 앱, **DB 변경**) | 中 |
| 5. 리포트 PDF 서버 저장 | 프론트 `window.print()` 기반 | 서버 렌더링(PDF 생성) 인프라 필요 | 서버에서 PDF 생성·저장(예: weasyprint/headless), 다운로드 링크 | 中 |
| 6. 리포트 다운로드 이력 저장 | 없음 | 이력 모델 = **DB 변경** | `ReportDownloadLog(user, report, downloaded_at)` 추가 | 低 |
| 7. 이전 리포트 비교 전용 API | 프론트가 `/reports` 목록 집계로 처리 | 전용 집계 API 부재 | `GET /users/me/growth`(점수 시계열 집계) 신설 | 中 |
| 8. 관리자 대시보드 | admin API 일부 존재(회원/통계) | 발표 범위 밖 화면 고도화 | 통계 시각화/프롬프트 관리/감사로그 UI 확장 | 低 |
| 9. 포인트/리그 기능 | 없음 | 신규 도메인 | 게이미피케이션 모델/랭킹(**DB 변경**) | 低 |
| 10. STT/TTS 품질 고도화 | 브라우저 Web Speech + 미지원 fallback | 정확도/안정성 한계 | 서버측 STT(Whisper) 파이프라인, TTS 음성 선택 | 中 |
| 11. 실제 채용공고 API 전환 | Mock Provider(`source=MOCK`) | 사람인 API 승인 지연 | 동일 `JobProvider` 인터페이스로 `SaraminService` 교체(설정값 전환) | 高 |
| 12. S3 원본 파일 보존 | 로컬 `MEDIA_ROOT` | django-storages/S3 설정 필요 | `django-storages`+S3, 업로드 영속화/CDN | 中 |
| 13. 리포트 성장 분석 고도화 | 점수 추이 막대 + 약점 TOP3(프론트) | 심화 분석 로직 필요 | 약점 카테고리 추세, 개선율, 코칭 코멘트(LLM) | 中 |
| 14. 기업별/직무별 맞춤 면접 고도화 | JD 기반 질문 생성 | 도메인 데이터/프롬프트 확장 필요 | 직무·기업 메타 기반 질문 뱅크/프롬프트 튜닝 | 中 |

## 비고
- DB 변경이 수반되는 항목(2 soft-delete, 3, 4 blacklist, 6, 9): 진행 확정 시 **변경 제안서(모델/필드/마이그레이션/영향도) 선작성 → 승인 → migration** 순으로 진행.
- 1·11은 사용자 경험/확장성 측면에서 차순위 1순위 후보.
