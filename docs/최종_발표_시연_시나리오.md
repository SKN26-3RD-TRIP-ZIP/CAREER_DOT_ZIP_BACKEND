# 최종 발표 시연 시나리오 (고정본)

> 발표용 고정 시나리오. **비밀번호·API Key·DB 접속정보·개인정보는 적지 않습니다.**
> 시연 계정은 이메일까지만 표기하고 비밀번호는 "별도 공유"로 둡니다.
> (참고: 간이 버전 `docs/최종_시연_시나리오.md` 의 확장/고정본)

## 1. 시연 목적
JD·이력서 기반 AI 모의면접의 전체 사용자 여정(가입→인증→입력→면접→리포트→성장 대시보드)이 하나의 흐름으로 동작함을 보인다. 사람인 API 미승인은 Mock Provider 로 합법적으로 대체하고, 승인 시 Provider 교체만으로 확장됨을 강조한다.

## 2. 시연 준비물
- 백엔드 실행(로컬/개발 서버), 프론트 `npm run dev` 실행, 크롬 최신.
- 발신 계정(tripdotzip) 메일함 접근(6자리 인증번호 확인용).
- 안정 네트워크. 발표 직전 1회 전체 플로우 리허설 완료.
- 백업: 미리 생성해 둔 리포트 세션 URL(`/report/<sessionId>`).

## 3. 시연용 계정 (비밀번호 별도 공유)
| 용도 | 이메일 | 비고 |
|---|---|---|
| 메인(데이터 보유) | (시연 계정 이메일) | 리포트 2개+ → 성장 추이/약점 노출 |
| 신규 가입 시연 | 현장 즉석 가입 | 6자리 인증 흐름 |
| 관리자(선택) | (관리자 이메일) | 회원/통계(선택) |
> 비밀번호는 문서에 적지 않음 — 발표자 별도 보관.

## 4. 시연용 데이터
- 메인 계정: 프로필 등록 완료, JD 1건+ , 이력서(PDF/DOCX) 1건+, 완료된 면접 2건+(리포트 존재).
- 신규 계정: 빈 상태(빈 상태 CTA/안내 시연용).
- Mock 공고: `(샘플)` 표기 + `source=MOCK` 데이터(실데이터 아님 명확히).

## 5. 시연 순서 (추천 플로우)
1. **로그인** → 2. **마이페이지 상태 확인**(요약/최근 로그인) → 3. **JD 등록**(직접 입력 또는 Mock 공고 선택) → 4. **이력서 업로드**(PDF/DOCX) → 5. **면접 설정**(JD/이력서/자소서, persona, text/voice) → 6. **면접 진행**(진행률·답변 저장·짧은 답변 경고) → 7. **꼬리질문 확인** → 8. **최종 리포트 확인**(점수/강약점/레이더/추천) → 9. **PDF 저장 버튼** → 10. **마이페이지 성장/약점/추천 질문 확인** → (마무리) **로그아웃**.

## 6. 화면별 발표 멘트(요약)
- 로그인: "이메일 인증을 마친 계정만 로그인됩니다. 세션 만료 시 자동으로 안내합니다."
- 마이페이지: "활동 요약·최근 로그인·최근 리포트가 한 화면에 모입니다."
- JD: "직접 입력, 또는 사람인 승인 전이라 Mock 공고로 동일 흐름을 보여드립니다(데이터에 MOCK 표기)."
- 이력서: "PDF·DOCX를 업로드하면 텍스트가 추출되어 면접에 활용됩니다."
- 면접 설정: "JD·이력서·자소서와 면접관 페르소나, text/voice 모드를 선택해 세션을 만듭니다."
- 면접: "진행률과 저장 상태가 표시되고, 답변이 짧으면 경고합니다. 진행 중 이탈도 방지합니다."
- 꼬리질문: "답변을 더 구체화하도록 꼬리질문이 생성됩니다."
- 리포트: "종합 점수, 강·약점, 역량 레이더, 약점 기반 추천 질문까지 제공하고 PDF로 저장됩니다."
- 마이페이지(재방문): "리포트가 쌓이면 성장 추이와 약점 개선 흐름이 보입니다."

## 7. 실패 시 대체 시나리오
- 인증 메일 지연 → 재발송(쿨다운) 또는 이미 인증된 메인 계정으로 진행.
- STT/TTS 미동작 → 텍스트 답변 입력으로 대체(안내 노출).
- 세션/리포트 생성 실패 → 백업 리포트 URL(`/report/<sessionId>`)로 결과 화면 직접 시연.
- 네트워크/401 → 세션 만료 안내 후 재로그인, 토큰 유효 상태로 재개.
- Mock 공고 검색 실패 → JD 직접 입력으로 대체.

## 8. 발표 중 강조 포인트
- JD/이력서 기반 **면접 세션 생성**(개인화).
- 실전형 답변 흐름 + **꼬리질문**으로 면접감 강화.
- 리포트의 **강점/약점/추천 질문/역량 레이더**.
- 마이페이지의 **성장 추적**.
- 사람인 API 지연을 **Mock Provider 로 합법적 대체**, 승인 시 **Provider 교체로 확장**.

## 9. Q&A 예상 질문
- "사람인 데이터인가요?" → 아니요. 직접 작성한 Mock(`source=MOCK`)이며, 승인 시 동일 인터페이스로 교체합니다.
- "면접 점수는 어떻게 산출되나요?" → 답변 평가 지표 기반 종합 점수 + 카테고리별 역량 점수(레이더).
- "음성 인식이 안 되는 환경은?" → 미지원 브라우저는 텍스트 입력으로 자동 대체 안내합니다.
- "개인정보/보안은?" → 비밀번호 해시, JWT(refresh는 HttpOnly 쿠키), 이메일 인증(6자리, 만료/시도제한), 키는 `.env`로만 관리.
- "배포는?" → EC2+Docker 기반 설계 완료(`docs/AWS_배포_설계_및_검증.md`), 일부 인프라 보완 후 실배포 예정.
