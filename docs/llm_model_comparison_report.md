# LLM 모델 성능 비교 평가서 — AI 면접관 파트

## 1. 평가 목적

본 평가는 AI 모의면접 시스템의 핵심 기능 중 **면접 질문 생성**과 **답변 기반 꼬리질문 생성**에 적합한 LLM 모델을 선정하기 위해 진행한다.

현재 MVP에서는 `gpt-4o`를 기준 모델로 사용하고 있으며, 동일한 입력 데이터와 동일한 프롬프트 조건에서 여러 모델의 결과를 비교하여 최종 적용 모델의 타당성을 검토한다.

특히 실제 서비스 운영 시 LLM 호출 비용이 지속적으로 발생하므로, 단순 응답 품질뿐 아니라 **응답 품질, 안정성, 비용 효율성, 운영 가능성**을 함께 비교한다.

---

## 2. 평가 범위

이번 비교 평가는 전체 서비스가 아닌, 담당 파트인 **AI 면접관 기능**에 한정한다.

본 평가는 LLM 모델의 질문 생성 및 꼬리질문 생성 품질 비교를 목적으로 하므로, 사용자 답변은 음성 입력 대신 동일한 텍스트 답변을 사용하여 비교하였다. STT 품질 평가는 본 비교 범위에서 제외하였다.

### 평가 대상 기능

| 구분 | 평가 내용 |
| --- | --- |
| 질문 생성 | JD, 이력서, 자기소개서, 프로젝트 경험을 기반으로 면접 질문을 생성하는지 확인 |
| 꼬리질문 생성 | 사용자 답변의 부족한 부분을 파악하고 적절한 추가 질문을 생성하는지 확인 |
| 페르소나 반영 | 선택된 면접관 페르소나의 말투와 질문 방식이 유지되는지 확인 |
| 응답 안정성 | JSON 형식이 안정적으로 반환되어 Backend에서 파싱 가능한지 확인 |
| 비용 효율성 | 서비스 운영 시 토큰 사용량 대비 비용이 적절한지 확인 |
| 운영 적합성 | 응답 속도, 비용, 품질을 종합적으로 고려 |

## 6. 평가 기준

각 평가 항목은 **1~10점 척도**로 평가하며, 모델 간 미세한 차이를 반영하기 위해 **0.5점 단위 평가를 허용**한다.

단순 총점만으로 모델을 선정하지 않고, 본 서비스의 핵심 기능인 **질문 생성 품질**, **개인화 수준**, **꼬리질문 적절성**, **실제 면접 흐름 적합성**을 우선적으로 고려한다.

### 6-1. 점수 산정 기준

| 점수 구간 | 기준 |
| --- | --- |
| 9.0~10.0 | 매우 우수. 서비스에 바로 적용해도 될 수준이며 수정이 거의 필요하지 않음 |
| 7.0~8.5 | 우수. 전반적으로 적합하나 일부 표현, 구체성, 응답 길이에서 보완 가능 |
| 5.0~6.5 | 보통. 기능적으로 사용 가능하지만 품질 또는 안정성 측면에서 한계가 있음 |
| 3.0~4.5 | 미흡. 입력 데이터 반영이 약하거나 질문 품질이 낮아 서비스 적용 전 수정 필요 |
| 1.0~2.5 | 부적합. 입력과 무관하거나 파싱 오류 등으로 실제 서비스 적용이 어려움 |

### 6-2. 항목별 세부 평가 기준

| 평가 항목 | 9~10점 기준 | 7~8.5점 기준 | 5~6.5점 이하 기준 |
| --- | --- | --- | --- |
| 직무 적합성 | JD의 핵심 요구사항과 지원 직무를 정확히 반영함 | 직무와 관련은 있으나 일부 질문이 일반적임 | 직무와 무관하거나 포괄적인 질문이 많음 |
| 개인화 수준 | 이력서, 프로젝트, 자기소개서의 구체적 경험을 자연스럽게 반영함 | 일부 입력 정보를 반영하지만 구체성이 부족함 | 사용자 입력과 거의 무관한 일반 질문을 생성함 |
| 질문 깊이 | 역할, 기술 선택 이유, 문제 해결 과정, 기여도를 깊게 묻되 답변 부담이 과도하지 않음 | 질문 의도는 좋으나 깊이가 약하거나 반대로 질문이 다소 장황함 | 단순 개념 확인 또는 표면적인 질문에 그침 |
| 꼬리질문 적절성 | 사용자 답변의 부족한 부분을 정확히 짚고 자연스럽게 이어 질문함 | 답변과 관련은 있으나 부족점을 깊게 파고들지는 못함 | 이전 답변과 연결성이 약하거나 엉뚱한 질문을 생성함 |
| 페르소나 일관성 | 선택한 면접관 페르소나의 말투, 압박 정도, 질문 방식이 일관되게 유지됨 | 대체로 유지되지만 일부 문장에서 톤이 흐려짐 | 페르소나 차이가 거의 드러나지 않거나 톤이 어색함 |
| JSON 안정성 | 모든 응답이 Backend schema에 맞게 파싱 가능함 | 일부 필드 보정이 필요하지만 처리 가능함 | JSON 파싱 실패 또는 필수 필드 누락으로 API 처리 불가 |
| 응답 속도 | 실제 면접 흐름에서 대기 부담이 거의 없음 | 약간의 대기 시간이 있으나 서비스 사용에는 무리 없음 | 대기 시간이 길어 면접 흐름이 끊김 |
| 비용 적합성 | 품질 대비 운영 비용이 합리적이며 확장 가능성이 높음 | 품질은 적절하나 사용자 증가 시 비용 부담 가능성 있음 | 비용 대비 품질이 낮거나 운영 부담이 큼 |

### 6-3. 가중치 적용 방식

모델별 최종 점수는 단순 평균이 아니라, 서비스 중요도에 따라 가중치를 적용하여 산정한다.

| 평가 항목 | 가중치 | 이유 |
| --- | --- | --- |
| 직무 적합성 | 15% | 면접 질문이 지원 직무와 맞는지가 핵심 |
| 개인화 수준 | 15% | 사용자 입력 기반 모의면접 서비스의 차별점 |
| 질문 깊이 | 15% | 단순 질문이 아닌 실무형 면접 질문 생성 여부 확인 |
| 꼬리질문 적절성 | 15% | AI 면접관 파트의 핵심 기능 |
| 페르소나 일관성 | 10% | 면접관 유형별 사용자 경험 차별화 |
| JSON 안정성 | 10% | Backend 파싱 및 서비스 안정성에 직접 영향 |
| 응답 속도 | 10% | 실시간 면접 흐름 유지에 필요 |
| 비용 적합성 | 10% | 실제 서비스 운영 가능성 판단 |
| 합계 | 100% |  |

최종 환산 점수는 아래 방식으로 계산한다.

```
환산 점수 = 항목별 점수 / 10 × 가중치
최종 점수 = 각 항목 환산 점수의 합
```

## 9. 비용 및 운영 적합성 평가

AI 면접관 기능은 사용자가 면접을 진행할 때마다 LLM API를 호출하므로, 실제 서비스 운영 시 모델 품질뿐 아니라 비용 효율성도 함께 고려해야 한다.

현재 담당 파트 기준으로 한 번의 면접 세션에서 발생하는 주요 LLM 호출은 아래와 같다.

| 단계 | 호출 내용 | 예상 호출 횟수 |
| --- | --- | --- |
| 질문 생성 | JD, 이력서, 자기소개서, 프로젝트 경험 기반 메인 질문 생성 | 1회 |
| 답변 평가 | 사용자 답변이 충분한지 판단 | 메인 질문 수만큼 |
| 꼬리질문 생성 | 답변이 부족할 경우 추가 질문 생성 | 조건부 |

MVP 기준으로 메인 질문 3개를 생성한다고 가정하면, 한 세션당 최소 4회에서 최대 7회 정도의 LLM 호출이 발생할 수 있다.

| 구분 | 예상 호출 |
| --- | --- |
| 메인 질문 생성 | 1회 |
| 답변 평가 | 3회 |
| 꼬리질문 생성 | 0~3회 |
| 총 호출 수 | 약 4~7회 |

이번 테스트에서는 동일한 입력 데이터와 동일한 사용자 답변을 사용하여 모델별 질문 생성 및 꼬리질문 생성 결과를 비교했다.

| 모델명 | 총 응답 시간 | 질문 생성 시간 | 꼬리질문 생성 시간 | 비용/운영 관점 |
| --- | --- | --- | --- | --- |
| `gpt-4o` | 9.86초 | 8.15초 | 1.71초 | 품질과 속도의 균형이 가장 안정적이며 MVP 기준 모델로 적합 |
| `gpt-4o-mini` | 10.24초 | 7.53초 | 2.71초 | 비용 절감 후보로 적합하며, 답변 평가/단순 분류 작업에 활용 가능 |
| `gpt-4.1-mini` | 14.13초 | 11.27초 | 2.87초 | 질문 깊이는 우수하지만 응답 시간이 길어 실시간 면접 흐름에서는 부담 가능 |

### 모델별 비용 관점 비교

| 모델명 | 비용 관점 | 운영 적합성 |
| --- | --- | --- |
| `gpt-4o` | 상대적으로 비용 부담은 있으나 질문 품질과 꼬리질문 품질이 안정적 | MVP 품질 검증용 기준 모델로 적합 |
| `gpt-4o-mini` | 비용과 응답 속도 측면에서 유리 | 답변 평가, 단순 분류, 요약 등 경량 작업에 적합 |
| `gpt-4.1-mini` | 품질과 비용의 절충 후보 | 긴 입력 처리와 상세 질문 생성에는 적합하나 응답 시간이 다소 길 수 있음 |

### 비용 최적화 방향

실제 운영 단계에서는 모든 기능에 동일한 고성능 모델을 사용하는 것보다, 기능별 중요도에 따라 모델을 분리하는 전략이 적합하다.

| 기능 | 모델 운영 전략 |
| --- | --- |
| 메인 질문 생성 | 질문 품질이 중요하므로 `gpt-4o` 유지 검토 |
| 꼬리질문 생성 | 답변 맥락 파악이 중요하므로 `gpt-4o` 또는 중간급 모델 검토 |
| 답변 충족도 판단 | 구조화된 판단이므로 `gpt-4o-mini` 등 경량 모델 적용 검토 |
| 단순 분류/요약 | 비용 절감을 위해 경량 모델 적용 검토 |
